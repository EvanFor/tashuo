# TA说 产品需求文档（MVP）

## 产品定位
TA说是以真人表达、内容交流和观点碰撞为核心的社区。内容可以是一句名言、一段影视台词、人生故事、日常记录、问题或观点；内容用于开启交流，而不是单纯追求浏览量。

## 产品原则
- 内容引出交流：优先支持有上下文的讨论和回复。
- 身份连续：日常交流使用稳定的社区昵称。
- 有边界的匿名：仅指定主题开放匿名发帖、评论和回复。
- 保护分歧：尖锐批评和观点不同本身不构成违规。
- 隐私最小化：不要求用户公开真实姓名，不收集与服务无关的数据。
- 治理可纠错：重要处罚提供理由、期限和申诉入口。

## 账号与身份
- 第一版使用邮箱注册、邮箱验证、登录和密码重置。
- 一个用户对应一个平台账号。
- 社区公开身份包括昵称、头像和简介。
- 匿名是内容展示模式，不是独立账号，不可用于绕过处罚。
- 匿名内容在公开主页和公开活动记录中隐藏作者关联。
- 匿名标识只在必要的单个讨论范围内保持连续，不生成跨主题全站匿名 ID。

## MVP P0
1. 邮箱注册、验证、登录、密码重置和会话撤销。
2. 个人资料和稳定昵称。
3. 主题列表、帖子详情、发帖、评论与回复。
4. 主题级匿名开关和服务端授权。
5. 公开主页过滤匿名内容。
6. 点赞、收藏（在基础讨论流程稳定后交付）。
7. 举报、审核队列、内容处理、禁言/封禁和处罚通知。
8. 申诉与复核。
9. 管理角色、最小权限和敏感操作审计。
10. 限流、基础垃圾信息防护、备份与恢复流程。

## P1 暂缓
- 站内私信、复杂声誉积分、跨主题匿名身份、复杂推荐算法、完全自动化的高风险审核决定。

## 匿名隐私要求
匿名只影响公开展示层。服务端保留必要的内部作者关联以支持治理，但不得把内部作者 ID、邮箱、匿名映射键暴露给普通客户端。搜索、分享、通知、缓存、日志和管理工具均需遵守相同规则。界面需说明匿名并非绝对不可识别。

## 验收原则
- 未登录或权限不足的请求不得写入内容。
- 未开放匿名的主题拒绝匿名发布，不能只依赖前端按钮隐藏。
- 普通用户无法通过主页、搜索、通知或 API 反查匿名作者。
- 举报不自动等同于违规；处罚应有理由且重要处罚可申诉。
- 上线前完成权限、匿名泄露、输入安全、会话和备份恢复测试。
